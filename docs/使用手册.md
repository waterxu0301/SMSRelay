# SMS 接力 — 使用手册

> 适用版本：1.0.0（`SMSRelay.app`）· 适用系统：macOS 13 及以上
> 本手册面向最终用户，所有功能描述均与实际实现一致。

## 1. 应用简介

「SMS 接力」是一款 macOS 托盘应用。它读取本机「信息」App（iMessage）数据库 `~/Library/Messages/chat.db` 中同步自 iPhone 的短信，提取其中的 **6 位数字验证码**，并实时转发到你配置的投递目标：

- **飞书** 群机器人 Webhook
- **钉钉** 群机器人 Webhook（支持加签密钥，密钥保存在钥匙串中）
- **企业微信** 群机器人 Webhook
- **邮件**（SMTP，如 QQ 邮箱授权码方式）

前提条件：iPhone 上已开启「信息 → 短信转发」并选中此 Mac，短信才会同步到 Mac。

**只转发满足以下条件的消息**（缺一不可）：

1. 短信正文中包含「验证码」三个字（不包含的短信完全不读取处理）；
2. 能从正文提取出 6 位数字验证码（左右不紧邻其他数字；若有多组，取**最后一个**）；
3. 消息未超过「验证码有效期」（默认 300 秒，可配置）；
4. 通过发件方/关键词白名单过滤（如启用）；
5. 不处于免打扰（静默）时段（如配置）。

推送到群机器人的文案为「标头 + 短信原文」直连的单行结构（change `push-message-with-original-text` 引入原文透传，`fix-push-format-duplicate-code` 修正为标头直连）：

```
【SMS接力】{短信原文}
```

- 标头 `【SMS接力】` 是程序专属标识，便于在多机器人共用的群里区分来源；其后**直接接完整短信原文**，不另起一行、不加「原文：」前缀。
- 短信原文**逐字完整保留**，包含发送方说明、验证码、有效期表述、时间戳等全部原始字段，不做任何删减或改写。
- **验证码只来自原文**：模板不再另行渲染验证码，也不再附加「请以原文时效为准」之类的时效提示 —— 原文已自述时效，重复输出会让下游取码程序在同一个验证码出现两次时产生歧义。

示例（原文「由数字化监控平台发送，验证码：583980，有效期为120秒，发送时间2026-10-30 10:06:39」）：

```
【SMS接力】由数字化监控平台发送，验证码：583980，有效期为120秒，发送时间2026-10-30 10:06:39
```

> **下游取码**：整条推送中验证码只出现一次，按「首个 6 位数字」「末个 6 位数字」或「`验证码[:：]` 后的数字」解析结果一致。
> 短信原文仅在内存中流转并进入推送内容，**不写入本地数据库**（含日志与缓冲）。
> 手动「重推」与测试推送因无原文，推送为「【SMS接力】验证码 {code}」单行格式。
> 邮件通道维持既有边界：正文仅含验证码、来源和时间，不包含短信原文全文。

## 2. 安装

### 2.1 系统要求

- macOS 13.0 或更高版本（Apple Silicon / Intel 均可）
- 已登录并与 iPhone 完成短信转发配对的「信息」App

### 2.2 安装步骤

1. 收到分发的 `SMSRelay.zip` 压缩包，双击解压得到 `SMSRelay.app`。
2. 将 `SMSRelay.app` 拖入「应用程序」文件夹（`/Applications`）。
3. **首次启动**：由于应用采用 ad-hoc 签名（无开发者证书），直接双击可能被 Gatekeeper 拦截并提示「无法打开」。请改用：
   - 在 Finder 中**右键点击** `SMSRelay.app` → 选择「打开」→ 在弹窗中再点「打开」；
   - 若系统仍拦截，前往 **系统设置 → 隐私与安全性**，在页面底部找到「已阻止使用 SMSRelay」的提示，点「仍要打开」。
4. 启动后应用出现在**屏幕顶部菜单栏右侧的托盘区**（铃铛图标 🛎）。应用不显示 Dock 图标；**关闭主窗口只是隐藏到托盘，监听不会中断**，真正退出请使用托盘菜单的「退出」。

## 3. 首次启动与权限授权

首次启动需要授权两类权限，应用会主动引导。

### 3.1 完全磁盘访问权限（FDA，必需）

读取 `chat.db` 必须授予「完全磁盘访问权限」。未授权时应用会弹出引导窗口「需要完全磁盘访问权限」：

1. 点击窗口中的 **「打开完全磁盘访问设置」**，系统将打开「系统设置 → 隐私与安全性 → 完全磁盘访问」。
2. 点击「+」添加 `/Applications/SMSRelay.app`（需要输入开机密码或 Touch ID 确认）。若列表中已存在 SMSRelay 但开关为关，打开开关即可。
3. **重新授权后需重启应用才能生效**：先通过托盘菜单「退出」关闭应用，再重新打开。
4. 回到引导窗口点击 **「我已授权，重新检测」**，检测通过后弹窗自动关闭，「开始监听」入口恢复可用。

引导窗口中的原因说明对照：

| 提示 | 含义 |
| --- | --- |
| 系统未授予「完全磁盘访问权限」 | TCC 授权被拒，按上述步骤授权 |
| 未检测到完全磁盘访问授权 | 其他读取失败，同样需授权后重试 |
| 未找到信息数据库（chat.db） | 本机没有信息 App 数据，请确认 Mac 已登录并同步 |
| 数据库当前被占用 | 稍等片刻后重新检测即可 |

### 3.2 通知权限（用于失败告警）

应用启动时会请求系统通知权限（提醒 + 声音）。**系统通知只用于「投递失败告警」**，不会用验证码内容打扰你：

- 点「允许」：投递失败时收到系统通知（标题「SMS 接力告警」，正文为脱敏摘要，不含验证码）。
- 点「不允许」：告警仍会在应用内以顶部红色横幅和「告警记录」页签展示，并提示可前往 **系统设置 → 通知 → SMS 接力** 重新开启。

## 4. 主窗口总览

点击托盘图标（铃铛）弹出菜单，选择「打开主界面」唤起主窗口。窗口自上而下分为**状态栏**与**七个功能页签**。

### 4.1 状态栏

| 指标 | 含义 |
| --- | --- |
| 核心 | 监听核心进程状态：启动中（灰）/ 核心运行中（绿）/ 核心重建中（橙）/ **监听不可用**（红） |
| 监听 | 监听中（绿）/ 已停止（红）/ 读取受限（橙，数据库异常降级） |
| 间隔 | 当前轮询间隔（秒） |
| 免打扰 | 已配置的静默时段，未设置则显示「未设置」 |
| 水位线 | 已处理到的 chat.db 消息位点（ROWID） |
| 已处理 | 本次监听累计处理的消息条数 |
| 缓冲 | 内存中可供手动重推的验证码条数（最多 100） |

状态栏右侧三个按钮：

- **开始监听 / 停止监听**：动态标题，当前停止时显示「开始监听」，监听中显示「停止监听」；点击即切换（与托盘菜单等价，两侧状态同步）。授权引导期间（未授予完全磁盘访问权限）该按钮置灰不可点击。
- **偏好设置**：打开偏好设置对话框（见第 7 节）。
- **手动重试**：仅在核心状态为「监听不可用」时出现，点击后重新拉起监听核心。

### 4.2 页签一览

| 页签 | 用途 |
| --- | --- |
| 投递目标 | 管理飞书/钉钉/企微推送目标 |
| 邮件通道 | SMTP 邮件转发配置 |
| 过滤与免打扰 | 轮询间隔、有效期、白名单、静默时段 |
| 投递统计 | 近 7 天各目标投递成功率 |
| 日志流 | 实时运行日志（最近 200 行）+ 导出/清空 |
| 告警记录 | 投递失败告警历史 |
| 调试动作 | 测试推送、立即扫描、手动重推 |

## 5. 各页签详细说明

### 5.1 投递目标

目标列表展示：平台（飞书🪶/钉钉📌/企业微信💼）、名称、打码后的 Webhook 地址、加签密钥状态、启用状态。

工具栏按钮：**新增 / 编辑（双击行亦可）/ 删除 / 启用停用 / 测试推送 / 刷新**。

**新增/编辑目标对话框**字段：

- **名称**：必填，全局唯一；
- **平台**：飞书 / 钉钉 / 企业微信（创建后不可修改）；
- **Webhook 地址**：必填，须为 http/https 地址。出于安全考虑**地址不明文回显**：编辑时显示打码占位（如 `当前：https://open.feishu.cn••••xxxx（不明文回显，修改请重输完整地址）`），聚焦输入框后重输完整地址即可修改；
- **加签 secret**：仅钉钉加签机器人需要，输入框掩码显示，**保存时直接写入 macOS 钥匙串，界面永不回显**（仅显示「已配置/未配置」）；留空表示保持不变。

**删除目标**：需二次确认；删除后自动清理数据库引用记录，并**一并删除钥匙串中的加签密钥条目**，不可恢复。

**测试推送**：见 5.7 调试动作中的说明（目标列表中的「测试推送」行为一致）。

### 5.2 邮件通道

展示当前配置摘要：状态（已启用/未启用）、SMTP 服务器（地址:端口 及加密方式）、发件人、收件人、授权码（仅显示钥匙串读取的掩码，如 `••••1234`）。

- **编辑配置**：打开对话框填写 SMTP 服务器、端口（默认 465）、加密方式（SSL / STARTTLS / 不加密）、发件人、收件人（多个用逗号或换行分隔）、**授权码**（掩码输入，留空保持不变，保存时直接写入钥匙串 `email.authcode`）。若邮件通道处于启用状态，保存时服务器/发件人/收件人不能为空。
- **启用/停用**：未配置 SMTP 时无法启用。

邮件转发正文仅含：验证码、来源（发送方）、时间；不含短信正文全文。

### 5.3 过滤与免打扰

- **轮询间隔(秒)**：默认 3，最小 1；
- **验证码有效期(秒)**：默认 300，超过有效期的旧验证码不投递；
- **发件方白名单**：勾选启用后，仅名单内的发送方（chat.db 中的 handle.id，即手机号/邮箱）会投递；名单支持逗号或换行分隔，保存时自动去重排序；启用时名单不能为空；
- **关键词白名单**：勾选启用后，短信正文须命中至少一个关键词才投递；
- **免打扰时段**：`HH:MM` 格式的开始/结束时间，须成对填写；支持跨午夜（如 22:00–07:00，界面会提示「跨午夜：静默将持续到次日 07:00」），静默期内收到的验证码只记录不投递。

保存后**立即热生效**，无需重启应用。校验失败时对应字段旁显示红色提示。

### 5.4 投递统计

按「消息 × 目标」粒度展示近 7 天各目标的：投递数、成功、失败、7 天成功率。成功率低于 99.5% 的行标红并提示「低于 99.5%」。底部汇总整体成功率。点「刷新」重新拉取。

### 5.5 日志流

实时显示运行日志（界面保留最近 200 行，按级别着色：DEBUG 灰 / INFO 黑 / WARN 橙 / ERROR 红）。

- **刷新**：重新拉取近 7 天日志（新→旧取最新 200 条后按时间正序显示）；
- **导出日志…**：将近 7 天运行日志导出为文本文件（默认文件名 `sms-relay-log-日期-时间.txt`）；
- **清空日志**：二次确认后清空运行日志、投递日志与告警记录（不可恢复）。

日志中的敏感信息（Webhook token、授权码、6 位验证码）均已自动脱敏。

### 5.6 告警记录

展示投递失败告警（时间、目标、原因摘要）。**当一条验证码在所有启用目标上均投递失败且重试用尽时**触发告警，同一事件 10 分钟内去重。告警同时通过三条通道送达：应用内横幅/本页签、系统通知（如已授权）、告警邮件（复用邮件通道配置，未配置则跳过）。告警内容不含验证码与短信正文。

### 5.7 调试动作

- **测试推送**：选择目标后可「dry-run 预览」——平台**不会收到真实消息**，仅弹出渲染内容预览（占位码 `******`）；确认后可「真实发送测试消息」（投递占位码 `000000`，**不计入统计、不触发告警**）；
- **立即扫描一次**：不等下一个轮询周期，立即扫描 chat.db 新消息；请求在途或已有扫描进行时按钮防抖置灰（忙碌时保持约 3 秒冷却，重复点击不会产生第二次扫描）；
- **手动重推**：列出内存缓冲中最近 100 条验证码（接收时间、发送方、验证码），选中后「重推选中」可重新投递。**缓冲仅存于内存，重启应用后清空**；超出缓冲范围的旧消息无法重推（提示「已超出重推窗口」）。缓冲中的验证码仅在界面内存中展示，不写日志、不落盘。

## 6. 系统托盘

托盘图标（铃铛）随监听状态变化，菜单共四项：

| 菜单项 | 行为 |
| --- | --- |
| 打开主界面 | 显示并前置主窗口 |
| 修改配置 | 打开主窗口并直接定位到「过滤与免打扰」页签 |
| 开始监听 / 停止监听 | 动态标题：当前停止时显示「开始监听」，监听中显示「停止监听」；点击即切换（授权引导期间该项置灰）。与主窗口状态栏的「开始监听 / 停止监听」按钮等价，任一侧操作后两侧同步 |
| 退出 | 停止监听与核心进程后完全退出应用 |

## 7. 偏好设置与开机自启

状态栏点「偏好设置」打开对话框，勾选 **「开机自动启动（登录时自动打开 SMS 接力）」**：

- 采用 macOS 13+ 标准登录项机制（SMAppService），无需安装任何后台守护；
- 若系统提示需要批准，前往 **系统设置 → 通用 → 登录项与扩展** 中允许 SMSRelay；
- 取消勾选即关闭开机自启。

## 8. 钥匙串（Keychain）凭据管理

应用将敏感凭据保存在 macOS 钥匙串中，条目归属服务名 `com.zero-reconn.sms-relay`：

| 账户名 | 内容 | 录入入口 |
| --- | --- | --- |
| `email.authcode` | SMTP 授权码 | 邮件通道 → 编辑配置 → 授权码 |
| `target.<目标ID>` | 钉钉机器人加签 secret | 投递目标 → 新增/编辑 → 加签 secret |

要点：

- 凭据**只在保存时经界面写入钥匙串**，之后界面与 IPC 通信中永不出现明文，仅回显尾 4 位掩码（`••••1234`）；
- 修改 = 在对应对话框重新输入并保存（覆盖旧值）；
- 删除目标时自动删除对应 `target.<目标ID>` 条目；邮件授权码不随「停用邮件通道」删除，如需彻底清除请在「钥匙串访问」中搜索 `com.zero-reconn.sms-relay` 手动删除。

## 9. 常见问题（FAQ）

**Q1：状态栏显示「监听不可用」怎么办？**
监听核心异常退出且自动重启 3 次（1/2/4 秒退避）均失败。点击状态栏右侧的 **「手动重试」** 按钮重新拉起；若仍失败，请导出日志（日志流 → 导出日志）并反馈给管理员。

**Q2：日志/告警出现 CRED_LOST（凭据丢失）？**
邮件通道的 SMTP 授权码在钥匙串中读取失败或不存在（常见于系统迁移、钥匙串条目被删除）。监听不会中断。解决：**邮件通道 → 编辑配置 → 重新输入授权码 → 保存**（重新写入钥匙串）。

**Q3：日志出现 SIGN_MISSING？**
钉钉目标配置了加签机器人，但钥匙串中没有对应加签 secret。解决：**投递目标 → 编辑该目标 → 重新填写加签 secret → 保存**。

**Q4：日志出现 SMTP_AUTH_FAILED？**
授权码错误（或邮箱未开启 SMTP 服务）。请在邮箱服务商处重新生成授权码后按 Q2 重新录入。

**Q5：日志出现 SCAN_AUTH_DENIED / 弹出授权引导窗？**
完全磁盘访问权限被撤销。按第 3.1 节重新授权并**重启应用**；授权前监听保持存活并自动重试，不会崩溃。

**Q6：验证码没有转发？**
依次检查：
1. Mac「信息」App 里能收到该短信（iPhone 短信转发已开启）；
2. 短信正文包含「验证码」三个字，且有 6 位数字；
3. 托盘/状态栏为「监听中」；
4. 目标处于「启用」状态、邮件通道已启用；
5. 发件方/关键词白名单未拦截（日志流中可见 SKIP_ 原因：`SENDER_NOT_ALLOWED` / `KEYWORD_NOT_ALLOWED` / `EXPIRED` / `SILENT`）；
6. 免打扰时段是否覆盖当前时间；
7. 可用「调试动作 → 立即扫描一次」手动触发并观察日志。

**Q7：手动重推提示「已超出重推窗口」？**
该消息不在内存缓冲（超过最近 100 条，或应用重启过）。缓冲清空后不可重推，属正常保护。

**Q8：提示「chat.db 缺失，扫描已暂停」？**
本机不存在信息数据库。确认 Mac 已登录 iMessage 且与 iPhone 完成转发配对后，重新开始监听。

**Q9：误点「清空日志」会清掉什么？**
运行日志、投递日志、告警记录全部清空（有二次确认）。投递**统计页数据基于投递日志**，也会一并归零；配置、目标、水位线不受影响。

**Q10：如何彻底退出应用？**
托盘菜单 → 退出。仅关闭主窗口不会退出。
