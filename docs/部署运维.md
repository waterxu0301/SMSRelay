# SMS 接力 — 部署运维手册

> 面向运维/开发者。覆盖环境要求、构建打包、签名分发、数据位置、日志、升级与卸载。

## 1. 架构概览

应用为**双进程架构**，由 py2app 打包为单 bundle（`SMSRelay.app`）：

```
SMSRelay.app（LSUIElement，无 Dock 图标）
├── GUI 主进程（desktop/，Tkinter + PyObjC）
│   ├── 主窗口/托盘/系统通知/授权引导
│   ├── Keychain 凭据写入（security CLI，唯一写入方）
│   ├── SMAppService 开机自启注册
│   └── Supervisor：拉起/守护子进程（崩溃退避重启）
└── 监听核心子进程（relaycore/，Python stdlib only）
    ├── stdio JSON Lines IPC（proto:1，见 docs/IPC接口说明.md）
    ├── 轮询 chat.db（只读）→ 提取验证码 → 过滤 → 分发
    ├── app.db（SQLite WAL）单写者长连接
    └── 三网关 + SMTP 邮件 + 三重告警
```

打包态子进程复用同一二进制：GUI 从 `Info.plist` 读取 `CFBundleExecutable`，以 `<app二进制> -u --relaycore-child` 拉起监听核心（入口 `desktop/app.py` 分发到 `relaycore.main`）。源码态则以 `python -u -m relaycore.main` 拉起（要求 cwd 为 `sms-relay/`）。

## 2. 环境要求

| 项 | 要求 | 依据 |
| --- | --- | --- |
| macOS | 13.0+（构建机与目标机） | `setup.py` 的 `LSMinimumSystemVersion=13.0`；SMAppService 要求 |
| Python | 3.13（实测 3.13.15） | `build/bdist.macosx-26.0-arm64/python3.13-standalone` |
| 打包依赖 | py2app（实测 0.28.10）、pyobjc-core + pyobjc-framework-Cocoa / UserNotifications / ServiceManagement（实测 12.2.2） | `setup.py` includes |
| 生产代码依赖 | **仅 Python 标准库**（sqlite3/smtplib/urllib/threading 等） | relaycore、desktop 业务代码 |
| 架构 | 与构建机一致（当前产物为 arm64 thin） | codesign 显示 `Mach-O thin (arm64)` |

## 3. 源码运行（开发态）

```bash
cd sms-relay/
python3 desktop/app.py        # GUI（无 PyObjC 时自动降级：无托盘/无系统通知/无自启）
```

开发态行为差异（源码判定 `.app/Contents/` 不在 `sys.executable` 中）：

- 无托盘、无系统通知（告警仅界面横幅）；
- 开机自启显示「dev 态不支持」；
- 子进程以 `sys.executable -u -m relaycore.main` 拉起；
- 数据目录与打包态相同（见第 6 节），开发与生产共用 `app.db`。

## 4. 构建打包

### 4.1 准备打包虚拟环境

```bash
cd sms-relay/
python3.13 -m venv .venv-pack
.venv-pack/bin/pip install py2app \
    pyobjc-framework-Cocoa \
    pyobjc-framework-UserNotifications \
    pyobjc-framework-ServiceManagement
```

（pyobjc-core 为框架包传递依赖，自动安装。）

### 4.2 构建

```bash
cd sms-relay/
.venv-pack/bin/python setup.py py2app
```

- 产物：`dist/SMSRelay.app`
- 打包选项要点（`setup.py`）：`packages: ["relaycore", "desktop"]` 整包入包；`argv_emulation: False`；plist 含 `LSUIElement=True`、`NSUserNotificationsUsageDescription`、`CFBundleIdentifier=com.smsrelay.desktop`、版本 `1.0.0`。

### 4.3 ad-hoc 签名

```bash
codesign --force --deep -s - dist/SMSRelay.app
```

- ad-hoc 签名（`Signature=adhoc`）不含开发者身份，Gatekeeper 首次启动需用户右键「打开」放行（终端用户操作见《使用手册》第 2.2 节）；
- 任何对 `.app` 内容的修改都会破坏签名，改动后需重新执行本命令；
- 若需免 Gatekeeper 引导的分发，需替换为 Apple Developer ID 证书的正式签名与公证，当前流程未包含。

### 4.4 zip 分发

```bash
cd sms-relay/dist
ditto -c -k --keepParent SMSRelay.app SMSRelay-1.0.0.zip
```

使用 `ditto`（而非 `zip`）以保留可执行位、符号链接与扩展属性。将 zip 交付给最终用户。

## 5. 应用包关键路径

```
SMSRelay.app/
├── Contents/MacOS/SMSRelay          # stub 解释器；子进程复用（--relaycore-child）
├── Contents/Info.plist              # LSUIElement=true、最低系统 13.0

    └── ...（PyObjC 框架与标准库）
```

## 6. 目录与数据位置

| 路径 | 内容 | 说明 |
| --- | --- | --- |
| `~/Library/Application Support/SMSRelay/app.db` | 应用数据库（SQLite，WAL 模式，伴生 `-shm`/`-wal`） | 9 张表：`config`、`push_targets`、`secret_refs`、`email_config`、`watermark`、`delivery_log`、`run_log`、`alert_log`、`stats_daily`；启动期由 `relaycore/dao/migrate.py` 幂等建表（`schema_version=1`） |
| `~/Library/Application Support/SMSRelay/instance.lock` | 单实例 flock 锁文件 | 持锁者为主实例；二次启动经 Unix socket 转发 focus 后退出 |
| `$TMPDIR/sms-relay.focus.sock` | 二次启动聚焦 socket | 残留自动删除重建 |
| 钥匙串（login keychain） | service=`com.zero-reconn.sms-relay` 的 generic password | 账户名：`email.authcode`（SMTP 授权码）、`target.<uuid>`（钉钉加签 secret）。**GUI 进程是唯一写入方**，核心子进程只读 |
| `~/Library/Messages/chat.db` | iMessage 数据库 | **只读**（`mode=ro`），每轮新建连接 |

隐私边界（实现约束）：`app.db` 与任何日志中不落验证码与短信正文；`secret_refs` 表仅存 Keychain 服务名/账户名/尾 4 位提示。

## 7. 日志与排障

### 7.1 日志获取

- **GUI 导出**（推荐，面向用户）：主窗口「日志流」页签 →「导出日志…」→ 导出近 7 天 `run_log` 文本文件；内容已脱敏。
- **直接查库**（运维）：

```bash
sqlite3 "$HOME/Library/Application Support/SMSRelay/app.db" \
  "SELECT datetime(created_at,'unixepoch','localtime'), level, code, message FROM run_log ORDER BY id DESC LIMIT 100;"
```

### 7.2 保留策略

`delivery_log` / `run_log` / `alert_log` 保留 7 天；核心子进程内置清理线程每小时执行一次滚动删除。清空操作（GUI 二次确认）删除三表全部数据。

### 7.3 常见运行期错误码

| 码 | 含义 | 处置 |
| --- | --- | --- |
| `SCAN_AUTH_DENIED` | chat.db 读取被 TCC 拒绝 | 重新授予 FDA 并重启应用 |
| `SCAN_DB_MISSING` | chat.db 缺失，扫描暂停 | 确认信息 App 数据存在后重启监听 |
| `SCAN_LOCKED` | chat.db 被占用 | 自动下轮重试，无需处理 |
| `NO_TARGET` | 有验证码但无启用目标 | 配置并启用目标 |
| `SIGN_MISSING` | 钉钉加签 secret 缺失 | 编辑目标重新录入 secret |
| `CRED_LOST` | 邮件授权码钥匙串读取失败 | 邮件通道重新录入授权码 |
| `SMTP_AUTH_FAILED` | SMTP 认证失败 | 更换/重新生成授权码 |
| `DELIVERY_ALL_FAILED` | 全目标投递失败（告警） | 检查 webhook 有效性与网络 |
| `WATERMARK_WRITE_FAIL_3X` | 水位线连续 3 次写失败 | 检查 Application Support 磁盘/权限 |

### 7.4 建表脚本分发（v1.0.0 已修复）

`relaycore/dao/migrate.py` 定位建表脚本 `001_init_app_db.sql` 的顺序：

1. 环境变量 `SMS_RELAY_DDL` 指定的绝对路径（可选，主要用于自定义部署）；
2. 包内资源 `relaycore/sql/001_init_app_db.sql`。

自 v1.0.0 起，DDL 脚本随 `relaycore` 包整目录分发进 bundle，**全新机器首启不再因
找不到建表脚本而失败**（早期版本此处有缺陷：脚本仅存在于开发机工作区，导致首启
`FileNotFoundError`、状态栏显示「监听不可用」）。

分发前仍建议在无 `~/Library/Application Support/SMSRelay/` 的干净账户上验证首启：
确认状态栏「核心运行中」、`app.db` 建出 9 张表（`sqlite3 .../app.db ".tables"`）。

## 8. 升级

1. 托盘菜单「退出」关闭应用；
2. 用新版 `SMSRelay.app` 覆盖替换 `/Applications/SMSRelay.app`；
3. 重新打开。配置、目标、统计、水位线均在 `app.db` 中保留（DDL 幂等，`schema_version` 兼容时跳过建表）；
4. 若旧版曾开启开机自启：登录项指向 `.app` 路径不变则无需处理；若移动过安装位置，需在偏好设置中重新开启。

注意：ad-hoc 签名下，替换后的新包首次启动仍需右键「打开」放行。

## 9. 卸载

按顺序执行（SMAppService 反注册需在删除 `.app` **之前**完成）：

1. **关闭开机自启**：应用内 偏好设置 → 取消勾选「开机自动启动」（内部调用 `SMAppService.mainApp().unregister()`）；同时经 IPC 通知核心记 `AUTOSTART` 日志留痕。
2. **退出应用**：托盘菜单 → 退出。
3. **删除应用包**：

```bash
rm -rf /Applications/SMSRelay.app
```

4. **清理数据目录**（可选，彻底卸载时执行）：

```bash
rm -rf "$HOME/Library/Application Support/SMSRelay"
```

（含 `app.db`、`app.db-wal`、`app.db-shm`、`instance.lock`；`$TMPDIR/sms-relay.focus.sock` 随系统临时目录清理。）

5. **清理钥匙串条目**（可选）：

```bash
# 查看目标条目账户名（target.<uuid>）
sqlite3 "$HOME/Library/Application Support/SMSRelay/app.db" \
  "SELECT account FROM secret_refs;" 2>/dev/null
security delete-generic-password -s com.zero-reconn.sms-relay -a email.authcode
# 各 target.<uuid> 条目逐一同法删除，或在「钥匙串访问」中搜索服务名批量删除
```

6. 若步骤 1 未执行即删除了 `.app`：前往 **系统设置 → 通用 → 登录项与扩展** 手动移除残留的 SMSRelay 登录项（状态显示 notFound）。
